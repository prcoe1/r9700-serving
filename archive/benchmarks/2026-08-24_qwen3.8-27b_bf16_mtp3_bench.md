## Run-to-run variance investigation (same build, same day)

An earlier attempt on the identical default config (0.92/262144) read much
lower (~1590 pp2048, tg32 52.96, tg128 59.95). To determine whether that was a
real config effect, I isolated each candidate cause:

| config | cache | pp2048 | tg32 | tg128 | notes |
|:-------|:------|-------:|-----:|------:|:------|
| 0.92/262144 (default) | warm | 1741/1432 | 52.96 | 59.95 | low outlier |
| 0.85/131072 | warm | 1907/1948 | 67.55 | 64.23 | 0.85 **cannot boot at 256K** (OOM) |
| 0.85/131072 | **cold** | 1944/1944 | 69.60 | 62.91 | caches cleared, aiter/inductor rebuilt |
| **0.92/262144 (default)** | warm | **1939/1957** | 63.31 | 65.98 | re-run, restored default |

Findings:
- **Not concurrency** — single request (`--max-num-seqs 2` is ineffectual at
  concurrency 1; invariant to it).
- **Not caches** — cold-cache re-run matched the warm run within noise.
- **Not util / max-len** — restored default (0.92/262144) re-ran at ~1950
  pp2048, matching 0.85/131072 (~1940) rather than the earlier ~1590.
- **The ~1590 reading was a run-to-run prefill scheduling outlier.** Prefill
  throughput at depth-0 is not tightly reproducible session-to-session on this
  build; ~1.9-2.0k t/s is the reliable band, with occasional dips toward ~1.4k.
  tg32/tg128 swing roughly ±10% (52-70 / 60-66).
- **0.92 is the floor for 256K + bf16 KV**: 0.85 fails engine init (8.93 GiB
  KV needed vs 8.59 GiB available). 0.85 only boots if max len drops to 131072.

Net: the default stack is healthy. pp2048 ~1950, tg32 ~63, tg128 ~66, in line
with the MTP3 depth-sweep decode band; coherence stable throughout.
