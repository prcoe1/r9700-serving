# Qwen3.8-27B — froggeric chat template v22.3 (stability test)

Stack: 2× R9700 (gfx1201), **fp8 KV** + tuned dense w8a8 block-FP8 configs,
MTP3 spec-decode, **256K max-model-len**, vLLM 0.27.1 + cherry-picked patches
#51812/#51837/#48375, torch 2.13, triton 3.8.0 (ROCm 7.14.0), AITER unified
attention, `--max-num-seqs 2`, `--enable-prefix-caching`, mamba-cache-mode
`align` (hybrid GDN default). froggeric `chat-templates/qwen.jinja`
**v22.1 → v22.3** (2026-08-20), server restarted.

## What v22.3 changes for this stack

- **KV-cache invariance**: history re-render now always keeps the empty
  ` thinking` block on thinking-off assistant turns, so re-rendered history is
  byte-identical to the tokens prefilled/generated at that turn (was: rendered
  as bare `assistant\n…`, guaranteed prefix-cache miss on every multi-turn
  conversation).
- **v22.2 tool-arg fix**: XML tool args now render non-string scalars as JSON
  (`true`/`null`/numbers) instead of Python `True`/`None`.

Prefix hits are **0%** — consistent with the tracked hybrid GDN + align-mode
no-op bugs `#45238`/`#51250` (AGENTS.md watchlist), not a template regression:
v22.3's rendered history byte-matches generated tokens, but the align-mode
mamba checkpoint lands in request-unique tokens, so the hash store never
hits. The template fix removes one blocker; the align-mode hybrid cache bug
remains the binding constraint.
