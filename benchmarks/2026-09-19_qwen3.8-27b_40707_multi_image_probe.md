# 2026-09-19 — Qwen3.8-27B #40707 probe: 4 large images, deadlock fix live

**TL;DR**: the first live test of the carried
[`#40709`](https://github.com/vllm-project/vllm/pull/40709) fix
(`patches/vllm/40707-mamba-block-aligned-split-deadlock.patch`, baked in via
`just rebuild && just up` on 2026-09-19). One prompt with **4× 3024×4032
photos (~47k prompt tokens)** completed with a coherent answer — no hang, no
corruption. The 1-image limit is no longer needed; the 99-image cap stays.

## Background

Unpatched, 2+ large images in one prompt hang the engine forever on these
hybrid GDN models: the encoder cache holds Image 1 while Image 2 waits, and
`_mamba_block_aligned_split` floors the sub-`block_size` inter-image gap to
0 new tokens, so the scheduler skips the request and Image 1's cache entry
is never freed (`vllm-project/vllm#40707`). Upstream fix `#40709` is still
open, so it is carried as a local build patch.

## Setup

- v0.29.0+rocm100.gfx1201 (rebuilt 2026-09-19 with the #40709 patch —
  marker confirmed in the running container's `scheduler.py`), AITER
  v0.1.20.post1 + local patches, MTP3, `--no-async-scheduling`, fp8 KV
  (calibrated), gfx1201 × 2 (TP2), qwen3.8-27b profile.
- Probe: `benchmarks/multi_image_probe.py` (new, self-contained: downloads
  its own images). 4 picsum seeds at 3024×4032 (~11.8k vision tokens each),
  one user message, `max_tokens` 2048, temperature 0.

| 1 (cold) | 47,432 | 35.0s | 64/64 thinking, cut off | `None` (still thinking) | no hang |

Notes:

- Runs 1–2 used small `max_tokens` and were cut off mid-think; they still
  prove the point (a deadlocked request never returns at all). Run 3 with
  room to finish thinking produced a correct, coherent sentence.
- Repeat latency (10.6s vs 35s cold) shows the identical-prompt prefix-cache
  hit working — consistent with the dense-retention default (#55760/#55861).
- Verdict bar for the checked-in probe: request completes with non-empty
  `content` (exit 0), else FAIL (exit 1, covers both hangs and empty replies).
