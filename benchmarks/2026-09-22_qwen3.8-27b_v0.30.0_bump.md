## Blocker found and fixed: #56190 aborts `import vllm` (exit 139)

Upstream #56190 (new in v0.30.0, "[ROCm][Bugfix] Fix profiler in TheRock
image") preloads `libtorch_cpu.so` RTLD_GLOBAL at `import vllm` time.
On this stack (TheRock torch 2.13 + `rocm` pip package) the preloaded
libtorch statically links LLVM, and `_rocm_sdk_core` (loaded later via
`torch._rocm_init`) registers the same `cl::opt` options again:
`Option 'spirv-expand-step' registered more than once` → LLVM ERROR →
abort. The server crash-looped with no logs past the LLVM line.
Bisected with `python -v` import traces in throwaway containers.
Fix: skip the preload when `rocm_sdk` is installed (costs only kineto
GPU-profiling registration, unused here); upstream fix stays active
where `rocm_sdk` is absent. No upstream issue exists yet.
