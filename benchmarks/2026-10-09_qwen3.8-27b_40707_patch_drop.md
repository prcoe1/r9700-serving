# 2026-10-09 — Qwen3.8-27B: dropped the #40707 local patch (fix is in the pin)

**TL;DR**: the carried
[`#40709`](https://github.com/vllm-project/vllm/pull/40709) local patch
(`patches/vllm/40707-mamba-block-aligned-split-deadlock.patch`, live since the
2026-09-19 rebuild) is **dropped**. The root-cause fix
[`#51603`](https://github.com/vllm-project/vllm/pull/51603) (apply Mamba
alignment *before* the encoder cap, so the collapse geometry is unreachable)
is in every release from **v0.28.0** and therefore in our v0.31.0 pin;
upstream closed `#40709` as superseded on 2026-10-07. Verified by a clean
no-patch run of `benchmarks/multi_image_probe.py` (PASS, below).

## Background

Unpatched vLLM before #51603 hangs forever on 2+ large images in one prompt
on these hybrid GDN models: the encoder cache holds Image 1 while Image 2
waits, and `_mamba_block_aligned_split` floors the sub-`block_size`
inter-image gap to 0 new tokens, so the scheduler skips the request and
Image 1's cache entry is never freed (`vllm-project/vllm#40707`). Since
#51603 the encoder cap is applied *after* alignment ("Apply Mamba alignment
before encoder caps." — present verbatim in the installed
`vllm/v1/core/sched/scheduler.py`, align-split call at L1151 runs before
`_try_schedule_encoder_inputs` caps `num_new_tokens` at L1174+), so the
guard the #40709 patch adds inside the split is dead code.

## Verification steps

1. **Ancestry**: #51603 merge commit `243c63baf5239f961305e25160c1bf6d34096df4`
   is an ancestor of v0.28.0 / v0.29.0 / v0.30.0 / v0.31.0 (compare API:
   `behind`), not of v0.27.1 (`diverged`).
2. **Code in the running build**: the #51603 ordering comment + call order
   confirmed in the container's installed scheduler.py; the #40709 guard
   confirmed present at L488 (image built with the patch).
3. **Baseline probe** (patch in place): PASS.
4. **No-patch state**: the #40709 hunk was reverted in place in the
   container's installed `scheduler.py` (root exec; the file is
   root-owned), then `docker compose restart vllm` (restart, not recreate —
   writable layer preserved) → healthy after 80 s → warmup request OK.
5. **No-patch probe**: PASS (table below).
6. **Patch-set integrity** (caught during the drop): `50409-mamba-replay-
   boundary-chunk-stop.patch` **hard-depended on the 40707 patch** — its
   hunk-1 context line is the 20-space-indented `end = aligned_end` inside
   the 40709 else branch, which only exists once 40707 is applied
   (`git apply` fails on pristine v0.31.0: `patch failed ... :491`).
   Rebased 50409 onto the pristine v0.31.0 tag (context line → pristine's
   16-space `end = aligned_end`; hunks shifted −11 lines, 491→480 /
   524→513). Verified: (a) all 13 remaining patches apply clean in the
   Dockerfile's ordered glob on a fresh v0.31.0 clone, `py_compile` OK;
   (b) the resulting tree is byte-identical to the old ordered apply
   (with 40707) except the 40707 hunk itself.
