# 2026-09-02 Qwen3.8-27B — #53877 backport (packed GDN decode beta stays FP32)

Carries upstream `vllm-project/vllm#53877` as a local patch
(`patches/vllm/53877-gdn-packed-decode-beta-fp32.patch`, build-time, applied
by `Dockerfile.fullbuild`). First release containing the fix upstream is
`v0.29.0rc1` (absent from our `v0.28.1rc0` pin). Drop the patch when a
`VLLM_REF` bump includes it.

## What the bug was

`fused_recurrent_gated_delta_rule_packed_decode_kernel` computed the GDN beta
gate in FP32 and then **rounded it to the input dtype (bf16)** before applying
it to the recurrent state:

```python
beta_val = tl.sigmoid(b_val).to(b.dtype.element_ty).to(tl.float32)  # bug
beta_val = tl.sigmoid(b_val)                                        # fix
```

Verified in the compiled Triton IR: the old (08-29) cached kernel has
`arith.truncf %beta_val : f32 to bf16` (fused_recurrent.py:373); the patched
one keeps `sigmoid__fp32` end-to-end. bf16 carries ~8 mantissa bits (~0.4%
ULP), so rounding beta perturbs **every** recurrent-state update; the state is
reused at every decode step, so the error **compounds with decode length**. The
upstream PR reports long-context accuracy/stability degradation for the
Qwen3.5–3.8 families — the exact model family served here (Qwen3.8-27B, 256K).

## Which kernel is actually affected

Two GDN decode kernels exist; both confirmed from the Triton cache IR:

- **Packed kernel** (`fused_recurrent_..._packed_decode`) — **the patched
  one**; the non-spec decode path (`_forward_core_decode_non_spec`, gated on
  `spec_sequence_masks is None`). Executed at CUDA-graph capture and for any
  non-spec decode tokens.
- **Fused sigmoid gating kernel**
  (`fused_sigmoid_gating_delta_rule_update`) — the MTP **spec-decode** path;
  its compiled IR already keeps beta in FP32 (no `truncf`), so it was never
  affected.

Under MTP3 the spec path is the primary decode path, but `qwen_gdn_attention_core`
is a splitting op, so the captured graph bakes in whichever path runs at
capture — the packed path is exercised there and on non-spec decode. Net: the
fix is correctness insurance on the packed/non-spec path, no change to the
already-correct spec path.

## Verification

- Regression test from the upstream PR
  (`test_packed_decode_keeps_beta_in_fp32`, + the 7 pre-existing packed-decode
  tests) run in a throwaway container from the rebuilt image with both R9700s
  attached: **8/8 passed**.
- Patched file confirmed in the image (`fused_recurrent.py:329`
  `beta_val = tl.sigmoid(b_val)`); patched kernel IR compiled this boot with
  the `truncf` removed.
- Coherence: **PASSED** (llama-benchy built-in) on both bench runs.

## Bench (v0.28.1rc0 + patch, fp8 KV, MTP3, TP=2, 256K, no-async)

Method: `llama-benchy 0.4.0`, `--pp 2048 --tg 32 128 --runs 3`, thinking off.

## Assessment

- **Decode at parity** (tg32/tg128 equal-or-better than the 08-27 no-async
  baseline); no throughput regression from the fix.
- **pp2048 ~2810 reads ~11% below the 08-28 default row (~3160)**, but this is
  inside the documented boot-to-boot prefill variance band (1950–3280 t/s
  across recent boots, see `2026-08-27_qwen3.8-27b_no_async_scheduling.md`),
  and the patch touches only the decode kernel, not prefill. Two consecutive
  runs agree, so it is a property of this boot, not noise.
- Coherence passed on every run.
