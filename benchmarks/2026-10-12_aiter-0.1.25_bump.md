## Build incident: TheRock SDK hipcc broken on fresh resolve

`just clear-vllm-caches && just rebuild` succeeded, but `just prewarm`
failed: aiter's runtime JIT could not build `module_aiter_core` — the venv
`rocm_sdk_core` hipcc shim's clang++ reports "cannot find ROCm device
library" on every GPU compile. Root cause: the 10.1 pip stream split device
files into `rocm-sdk-device-*` + devel reconcile (`rocm-sdk init`), and
`rocm[devel]` is not installed (`rocm-sdk init` errors out). The fresh
`--no-cache` pip resolve pulled this restructured layout; the 3-day-old
image predates it. Device bitcode exists (`_rocm_sdk_core/lib/llvm/amdgcn/
bitcode/`, `rocm-sdk-device-gfx1201` kpacks + `.devel_links`), but core
clang has no links to it.

Fix (no rebuild needed): prefer the classic `/opt/rocm/bin/hipcc`, which
compiles gfx1201 fine and is the *same* HIP 7.16 / clang 24 toolchain as the
shim — zero skew. `env/2xr9700.vllm.common` now pins
`PATH=/opt/rocm/bin:/opt/venv/bin:...`; `Dockerfile.fullbuild` ENV updated
to match for future rebuilds. aiter honors no `HIPCC` override (checked
`jit/core.py`), so PATH order is the surgical knob. Verified: JIT core
builds in ~12 s, `import aiter` clean, prewarm complete.
Follow-up: if a future `rocm[devel]` flow stabilizes, re-evaluate (repro:
`hipcc --offload-arch=gfx1201` on a trivial `.hip` file in any container).

Note: `allowed-archs-gfx1201.patch` needed a rebase (upstream added
`gfx1250` to the list). Regenerated via `git diff` (canonical headers —
hand-written hunk counts caused a "corrupt patch" scare). Both aiter
patches `git apply --check` clean on pristine v0.1.25.
