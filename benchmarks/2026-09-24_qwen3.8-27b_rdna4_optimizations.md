## Patch status on this image

- **#56005 FlyDSL block-FP8 GEMM — LIVE.** Server log: `Selected
  RDNA4Fp8BlockScaledMMKernel for Fp8LinearMethod` (replaces
  `TritonFp8BlockScaledMMKernel` for all 1x128/128x128 OCP-FP8 linears).
  Decode (M≤64) routes to the packed-row/split-K small-M kernels; prefill to
  the prefill/wave32 variants.
- **#57767 native RDNA custom all-reduce — COMPILED, DORMANT.**
  `vllm._rocm_C` builds `rdna_custom_all_reduce.cu` for gfx1100/1200/1201 and
  `torch.ops._rdna_custom_ar` is registered, but the 2× R9700 exposes **no
  P2P** (`torch.cuda.can_device_access_peer(0,1) == False` both directions,
  consistent with the `NCCL_P2P_DISABLE=1` in the common env): enabling
  `VLLM_ROCM_USE_RDNA_ALL_REDUCE=1` made the communicators fall back with
  `no visible P2P access to rank 1` and the group dispatch to PYNCCL. The
  env flag stays unset (comment in `env/2xr9700.vllm.common`); the patch
  costs nothing dormant — re-enabling is one line if P2P ever appears.
- **#55996 SplitKV FlyDSL paged decode — DORMANT.** Only patches the
  `ROCM_ATTN` backend (`rocm_attn.py`); this stack pins
  `ROCM_AITER_UNIFIED_ATTN`, whose impl overrides `forward`, so the SplitKV
  path is unreachable. `VLLM_ROCM_USE_RDNA4_SPLITKV_FLYDSL` stays off
  (default); a future UA-backend backport of the SplitKV decode would be the
  way to activate it.
