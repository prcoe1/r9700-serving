# 2026-10-08 — UA image-correctness probe: live run

**TL;DR**: PASS. The AMD-reported gfx12 AITER unified-attention image-input
corruption (non-causal attention, ROCm/aiter#5683 — OCR reads 6/6→3/6 on an
R9700 with `VLLM_ROCM_USE_AITER=1`, reported in the vLLM #57838 thread on
2026-10-08) does **not** reproduce on our live path.

## Context

- vLLM #57838 (2026-10-08): an R9700 commenter reports silent image/OCR
  corruption with AITER unified attention + `VLLM_ROCM_USE_AITER=1`
  (gemma-4-12B FP8; a deterministic 6-item vision check drops 6/6→3/6,
  text-only tasks stay correct), matching AMD's own note that gfx12 AITER
  unified attention returns wrong results on image input. Tracked in
  ROCm/aiter#5683 (open; AMD's gfx12 team confirmed 2026-09-20 they will
  work on the non-causal path).
- `benchmarks/ua_image_correctness_probe.py` was written 2026-10-07 after
  the #56021 thread's AMD warning that UA with multimodal image input
  "silently passes and produces wrong attention output". It renders images
  with known text (embedded bitmap font, pure stdlib) and requires the live
  server to read them back exactly — `multi_image_probe.py` checks liveness
  only, so silent corruption would pass it.

## Run

- Live server: v0.31.0 final, `qwen3.8-27b` profile — UA pinned globally
  (`env/aiter-unified-attention.env`), MTP1 K=1, image cap 99 — 2026-10-08.
- Command: `python3 benchmarks/ua_image_correctness_probe.py`.
- Result: **12/12 single-image reads exact + two-image read exact.
  OVERALL: PASS** (exit 0).

## Notes

- The gemma-4 repro runs the default attention path with
  `VLLM_ROCM_USE_AITER=1` on per-channel (row-wise) FP8; our profile pins
  `ROCM_AITER_UNIFIED_ATTN` explicitly with every other AITER component off
  (`LINEAR=0`, `RMSNORM=0`, `MOE=0`, …). Our vision-encoder path evidently
  does not hit the broken kernel in this config — but "not hit today" is
  config-dependent, hence the standing guard:
- **Guard**: re-run this probe on any bump touching the UA or vision path,
  and when aiter#5683 lands (a fix must keep it green). Garbled reads mean
  image support should be dropped (image cap 0) until the fix is in.
